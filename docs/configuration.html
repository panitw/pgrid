Columns

A column definition supports the following keys.

KeyTypeDescription
idnumberUnique id; the array index is used if omitted.
fieldstringKey in your data row.
titlestringHeader label (HTML is allowed).
widthnumberColumn width in pixels.
cssClassstringClass added to every cell in this column.
editablebooleanAllow inline editing. Requires editing: true.
resizablebooleanAllow column resize. Defaults to true when columnResize is on.
textOverflow'ellipsis' | 'wrap' | 'clip'Override the grid default for this column.
editor{ attach, clear }Custom editor. See Extensions.
formatter{ render, update? }Cell renderer. See demo.
 
columns: [
    { id: 0, field: 'id',     title: 'ID',     width: 100, cssClass: 'col-id' },
    { id: 1, field: 'name',   title: 'Name',   width: 180, editable: true },
    { id: 2, field: 'salary', title: 'Salary', width: 130, cssClass: 'col-money',
        formatter: {
            render: e => e.cellContent.textContent = '$' + (e.data || 0).toLocaleString()
        }
    }
]

Rows

Per-data-row overrides — typically used to apply CSS classes or set per-row height. Match by zero-based data row index i. selectable: false keeps the selection extension off every cell of the row (mouse, arrow keys and selectCell); the arrow keys step over it.

rows: [
    { i: 0, cssClass: 'highlight-row', height: 48 },
    { i: 5, cssClass: 'forecast-row' }
]

Cells

Per-cell overrides match by row + column coordinates.

cells: [
    { r: 0, c: 2, cssClass: 'subtotal-cell', editable: false }
]

A cell model also takes selectable: false, as a row does, and stickySpan — see Column span.

Column span

A cell can be declared colspan columns wide. The spanning cell is rendered once at its anchor column with the summed width of the columns it covers; those covered columns render no cell of their own. Spanning is known to the layout math, not to CSS, so a span stays rendered while any part of it overlaps the viewport.

cells: [
    // Data row 0, column 1, three columns wide (covers columns 1-3).
    { r: 0, c: 1, colspan: 3 }
],
headerCells: [
    // A merged header cell across columns 2 and 3.
    { r: 0, c: 2, colspan: 2 }
]

Rules:

  • Opt-in. With no colspan anywhere, every rect, cell count and DOM node is exactly what it was without the feature.
  • Clamped to the column count. A span running past the last column ends at the last column.
  • Clamped to the pane. Columns split into the frozen block and the scrolling block, and each is rendered into its own pane, so a span never crosses freezePane.left — it ends at the boundary instead.
  • Unless it is sticky. Add stickySpan: true to a span that starts in the frozen block and reaches past freezePane.left, and it is rendered into a span layer laid over both panes instead: it starts at its own column, runs to the grid's visible right edge (ellipsis applies there, not at the frozen boundary), holds still on horizontal scroll like the frozen columns, and follows its row vertically. getColumnSpan still reports the span clamped to the frozen block, and the scrolling columns still render their own cells underneath. Anywhere else — no frozen columns, a span starting in the scrolling block, a span ending inside the frozen block — the flag is ignored. Group labels use this; see Row grouping.
  • Degenerate values mean no span. A colspan of 0, 1, a negative, a fraction below 2 or a non-number is ignored; nothing throws. A fractional value above 2 is floored.
  • The anchor owns the cell. The spanning cell uses its anchor column's field, cell model, cssClass and editability. The covered columns' own models are not consulted.
  • One cell to the keyboard. Moving right off a span lands on the first column after it; moving left into a span lands on the anchor.
  • Rectangular on the clipboard. Copying a span emits its value followed by one empty field per covered column (the Excel convention); pasting back discards those blanks rather than writing them.
  • Spans do not nest. If two spans overlap, the one whose anchor comes first wins the columns they share; a span declared on a column that another span already covers renders nothing and reports a span of 1.
  • A spanning cell carries data-colspan in the DOM. There is no row span.

Note on column resizing: a merged header cell carries no resize handle, and neither do the columns it covers — they have no header cell of their own. A handle sits at the right edge of the cell it is rendered in, which for a merged cell is the edge of the last column it covers, while the drag would resize the anchor; rather than move an edge you did not grab, the handle is skipped. With headerRowCount above 1, those columns stay resizable from any header row that does not merge them.

Headers

By default the grid has one header row. Increase headerRowCount for multi-row headers, then style each via headerRows.

{
    headerRowCount: 2,
    headerRows: [
        { i: 0, cssClass: 'header-group', height: 32 },
        { i: 1, cssClass: 'header-leaf',  height: 28 }
    ]
}

Freeze panes

The grid lays out as six panes: top-left / top / left / center / bottom-left / bottom. Freezing leading columns or top/bottom rows pins them while the rest scrolls.

freezePane: {
    left: 2,        // first 2 columns stay fixed when scrolling horizontally
    top: 0,         // additional fixed rows beyond the header
    bottom: 1       // last row stays fixed (e.g. a totals row)
}

Feature toggles

Each toggle loads a built-in extension. They're opt-in so you only pay for what you use.

{
    selection: { cssClass: 'cell-selected' },
    editing: true,
    copypaste: true,
    autoUpdate: true,
    columnFormatter: true,
    columnResize: { minWidth: 60, maxWidth: 400 },
    textOverflow: 'ellipsis'
}

For boolean checkbox columns, also load the named extension:

import { PGrid, CheckboxColumnExtension } from '@panitw/pgrid';

new PGrid({
    /* … */
    extensions: [new CheckboxColumnExtension()]
});

Row grouping

Setting foldableRows loads FoldableRowsExtension, which gathers records under synthetic group rows you can fold away. A collapsed group's records leave the row projection entirely — they are gone from the DOM, not hidden — so virtualization keeps working on large datasets. The DataTable itself stays flat: group rows are never inserted into your data.

foldableRows: {
    groupBy: ['department', 'location']
}

A group row renders two cells, not one per column: the chevron gutter, and the label cell, which carries a column span across the rest of the row so the label and its count read in full instead of being clipped to labelColumn's width. When labelColumn is inside the frozen block the label is a sticky span (stickyLabel): it reads across the whole visible width of the grid, frozen and scrolling columns alike, and holds still on horizontal scroll. When labelColumn is in the scrolling block it spans to the last column and scrolls with it, and with stickyLabel: false a frozen label stops at freezePane.left as any span does. The columns the span covers render no cell at all — there is nothing there for a cellRender hook or a column formatter to write into.

The extension injects its own leading chevron gutter column and freezes it, then compensates every index-bearing option for you. columns[].i, cells[].c, headerCells[].c, freezePane.left and labelColumn all stay authored as if grouping were switched off. Use model.getColumnIndex(field) if you need the post-injection index of a column.

KeyTypeDefaultDescription
groupBystring | string[]requiredField, or ordered list of fields, to group by. A list produces nested group rows, outermost first. With nothing to group by the extension injects no gutter and changes nothing.
gutterWidthnumber28Width of the injected chevron column. The chevron indents inside it, so deep nesting wants more.
labelColumnnumber0Which column carries the group label, numbered as you authored it — the default is your first column.
collapsedByDefaultbooleanfalseInitial fold state for every group.
indentSizenumber16Pixels of indent applied per nesting level, to both the chevron and the label.
cssClassstring'pgrid-group-row'Class applied to every cell a group row renders — the gutter, the label, and anything the label's span does not reach.
showCountbooleantrueAppend the descendant record count to the group label.
emptyLabelstring'(none)'Label used when the grouped field is null, undefined or ''. Those records group together.
groupLabel(value, path, count) => stringidentityFormats the label text. Text only — this is not a cell renderer.
groupRowHeightnumberconfig.rowHeightHeight of a group row.
stickyLabelbooleantrueWhen labelColumn is in the frozen block, let the label read across the whole visible width and hold still on horizontal scroll instead of clipping at the frozen boundary. No effect when the label is in the scrolling block.
selectableGroupRowsbooleanfalseLet group rows take cell selection. Off by default: no cell of a group row can be selected, the arrow keys step over group rows, and a selection whose record is folded away is cleared. Turn it on for Space folding.

Reach the extension for programmatic control. Every method below rebuilds the projection and re-renders, except isCollapsed, getGroups and getState:

const folding = grid.extension.getExtension('DEFAULT_EXT_FOLDABLE_ROWS');

folding.collapse(['Engineering', 'Berlin']);   // also expand() / toggle()
folding.collapseAll();                         // also expandAll()
folding.isCollapsed(['Engineering']);          // -> boolean
folding.getGroups();                           // [{path, label, level, count, collapsed}, ...]
folding.setGroupBy(['location']);              // regroup at runtime

const snapshot = folding.getState();           // {groupBy, collapsed: [path, ...]} — JSON-safe
folding.setState(snapshot);                    // restores the grouping AND the fold state

A user folds a group by clicking its chevron, or by selecting the group row and pressing Space. Spacebar folding needs selection enabled and selectableGroupRows: true, since it works off the current selection.
